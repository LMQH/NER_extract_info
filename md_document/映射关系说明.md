# MGeo模型标签到输出字段映射关系说明

## 概述

旧版本

本文档详细说明了 `mgeo_geographic_composition_analysis_chinese_base` 模型的标签（Label）如何映射到API接口返回的标准化字段。

**默认模型**: `mgeo_geographic_composition_analysis_chinese_base`

**转换函数**: `convert_mgeo_to_output_format()`

---

## 输出字段顺序

API返回的 `Data` 字段按以下顺序排列：

```
ProvinceName → CityName → ExpAreaName → StreetName → AreasInfo → Address → others → Mobile → Name
```

---

## 详细映射关系

### 1. ProvinceName（省份名称）

**映射标签**: `PB`

**标签说明**: 省

**示例**: "广东省"、"北京市"、"新疆维吾尔自治区"

**处理方式**: 取第一个匹配的实体，直接赋值

---

### 2. CityName（城市名称）

**映射标签**: `PC`

**标签说明**: 城市

**示例**: "深圳市"、"杭州市"、"上海市"

**处理方式**: 取第一个匹配的实体，直接赋值

---

### 3. ExpAreaName（区县名称）

**映射标签**: `PD`

**标签说明**: 区县（包括开发区）

**示例**: "龙岗区"、"余杭区"、"海淀区"

**处理方式**: 取第一个匹配的实体，直接赋值

---

### 4. StreetName（街道名称）

**映射标签**: `PF`, `PG`, `PH`, `PS`

**标签说明**:
- `PF`: 街道
- `PG`: 村庄
- `PH`: 行政俗称/商圈（如：九亭、古荡、莘庄、望京）
- `PS`: 其它行政

**示例**: "坂田街道"、"九亭"、"古荡"

**处理方式**: 按文本中的位置顺序（`start`字段）排序，将所有匹配的实体文本拼接

**代码逻辑**:
```python
street_entities = []  # 存储 PF, PG, PH, PS
# 按 start 位置排序后拼接
```

---

### 5. AreasInfo（区域信息）

**映射标签**: `BS`, `BL`, `RD`, `Brand`, `CategorySuffix`, `SS`, `SA`, `UD`, `UE`, `YA`

**标签说明**:
- `BS`: 公交地铁站
- `BL`: 公交地铁线路
- `RD`: 道路（包括高速公路、隧道、桥梁、立交桥）
- `Brand`: 著名品牌（如：(阜荣街)外婆家）
- `CategorySuffix`: 类别后缀词（如：(阜荣街)大学（二层)）
- `SS`: 分支词（如：(肯德基)xx店、(xx)紫金港校区、(xx)望京支行、(xx)二厂）
- `SA`: 方位修饰词（如：南，向南，东侧、路南、桥北）
- `UD`: 门址 附属描述（如：三期、北段、一段、(机场)出发、内环、外环、路口、交叉口、下道口、交汇处、高速出口）
- `UE`: 门址 东口、南门
- `YA`: 语义连接词（助词、疑问词、连接词、转折词、需求词、附近词、量词）

**示例**: "长坑路"、"阿里巴巴"、"西侧"、"的"

**处理方式**: 按文本中的位置顺序（`start`字段）排序，将所有匹配的实体文本拼接

**代码逻辑**:
```python
areas_info_entities = []  # 存储 BS, BL, RD, Brand, CategorySuffix, SS, SA, UD, UE, YA
# 按 start 位置排序后拼接
```

---

### 6. Address（详细地址）

**映射标签**: `UA`, `UB`, `UC`, `Entity`, `NumEng`

**标签说明**:
- `UA`: 门址 道路xx号/xx弄
- `UB`: 门址 xx座楼/xx区
- `UC`: 门址 xx号楼/xx棟/xx幢
- `Entity`: POI一般名称（如：黄山风景区、首开广场、清华大学、(幼儿园)春蕾）
- `NumEng`: 数字英文串（品牌、entity、明确的门址除外）

**示例**: "西2巷2号202"、"阿里巴巴西溪园区"

**处理方式**: 按文本中的位置顺序（`start`字段）排序，将所有匹配的实体文本拼接

**代码逻辑**:
```python
address_entities = []  # 存储 UA, UB, UC, Entity, NumEng
# 按 start 位置排序后拼接
```

---

### 7. others（其他信息）

**映射标签**: `Yewu`, `Desc`, `BD` 以及其他未映射的标签类型

**标签说明**:
- `Yewu`: 业务词
- `Desc`: 修饰词（如：24小时，便宜的）
- `BD`: 标点符号
- 其他未在映射表中定义的标签类型也会归入此字段

**示例**: "24小时"、"便宜的"、"。"

**处理方式**: 按文本中的位置顺序（`start`字段）排序，将所有匹配的实体文本拼接

**代码逻辑**:
```python
others_entities = []  # 存储 Yewu, Desc, BD 等未映射类型
# 按 start 位置排序后拼接
```

---

### 8. Mobile（手机号码）

**映射标签**: 从 `ZZ`（未知）类型或原始文本中提取

**标签说明**: `ZZ` 表示未知类型，系统会尝试从中识别电话号码

**提取规则**:
1. 首先从 `ZZ` 类型的实体中匹配电话号码模式（`1[3-9]\d{9}`）
2. 如果未找到，则从原始文本中提取电话号码

**示例**: "18273778575"、"13800138000"

**代码逻辑**:
```python
# 从 ZZ 类型或原始文本中提取电话号码
phone = EntityExtractor.extract_phone_from_text(text)
```

---

### 9. Name（姓名）

**映射标签**: 从 `ZZ`（未知）类型或原始文本中提取

**标签说明**: `ZZ` 表示未知类型，系统会尝试从中识别中文姓名

**提取规则**:
1. 首先从 `ZZ` 类型的实体中匹配中文姓名模式（`^[\u4e00-\u9fa5]{2,4}$`）
2. 如果未找到，则在非地址部分的文本中查找姓名
3. 排除所有地址相关实体覆盖的文本范围

**示例**: "黄大大"、"张三"、"李四"

**代码逻辑**:
```python
# 从 ZZ 类型或原始文本中提取姓名
# 排除地址实体覆盖的范围
name = AddressParser.find_name_in_non_address_text(text, address_ranges)
```

## 未使用的标签

以下标签在当前映射关系中未被使用，但会在模型输出中出现：

- `PA`: 国家（当前未映射到任何字段）
- `PE`: 乡镇（当前未映射到任何字段）

**注意**: 这些未映射的标签会被归类到 `others` 字段中。

## 处理流程

1. **实体提取**: 从模型输出中获取 `entities.output` 列表
2. **实体排序**: 按 `start` 字段对实体进行排序，确保文本顺序正确
3. **实体分类**: 根据实体类型（`type`字段）将实体分类到不同的集合
4. **字段填充**:
   - 单一值字段（ProvinceName, CityName, ExpAreaName）: 取第一个匹配的实体
   - 拼接字段（StreetName, AreasInfo, Address, others）: 按位置顺序拼接所有匹配的实体
   - 提取字段（Mobile, Name）: 从ZZ类型或原始文本中提取
5. **字段重排序**: 使用 `reorder_data_fields()` 确保输出字段顺序正确

## 注意事项

1. **字段顺序**: 输出字段严格按照 `ProvinceName → CityName → ExpAreaName → StreetName → AreasInfo → Address → others → Mobile → Name` 的顺序排列

2. **实体排序**: 所有需要拼接的字段（StreetName, AreasInfo, Address, others）都会按照实体在原始文本中的位置（`start`字段）进行排序后再拼接

3. **单一值字段**: ProvinceName, CityName, ExpAreaName 只取第一个匹配的实体，如果存在多个同类型实体，后续的会被忽略

4. **未映射标签**: 任何未在映射表中定义的标签类型都会被归类到 `others` 字段

5. **ZZ类型处理**: `ZZ`（未知）类型不会出现在 `others` 字段中，而是用于提取电话号码和姓名

6. **空值处理**: 如果某个字段没有匹配的实体，该字段将返回空字符串 `""`
